# ZERO

無料API、自動準備する端末内LLM、Google Apps Script（GAS）、非公開Googleスプレッドシートで動く日本語の会話型アシスタント。通訳君を参考にした黒基調の操作画面です。有料の推論APIは使いません。

## 構成

入力欄は1つに統一し、下部のモード切替バーは廃止しています。会話履歴・「できること」・設定はヘッダーから開けます。スマートフォンでもヘッダーの操作を収め、入力欄の下側は端末のセーフエリアに合わせます。

GitHubでソースを管理し、GitHub PagesからGASのWebアプリを表示します。GASのHTML画面から `google.script.run` を呼び出す構成により、クロスオリジンの保存APIにJSONPやno-corsを使う必要がありません。埋め込みが制限されるブラウザでは「別画面で開く」を使います。

- `index.html`：GitHub Pagesの入口
- `config.js`：GASの公開URL（秘密鍵は含みません）
- `App.html`：GASが表示する画面と会話処理
- `Code.gs`：API取得、利用制限、データベース処理
- `Config.gs`：データベースのファイルID。ファイル自体は非公開のまま利用
- `appsscript.json`：GAS実行設定
- `preview.html`：GAS未接続でも実データ取得を試せる画面。履歴は保存しません

## データベース

| シート | 用途 |
| --- | --- |
| Settings | アプリ名、見出し、履歴保存の有効・無効 |
| Providers | 利用するAPIの有効・無効、ライセンス、出典 |
| Conversations | 会話ID、所有者ハッシュ、題名、日時、会話条件 |
| Messages | メッセージID、所有者ハッシュ、会話ID、発言、日時、出典 |

各シートの1行目は列名です。列名・順序を変更するとGASは処理を停止します。

## 利用できる機能

天気の取得と最大3都市の比較、服装の目安、日の出・日の入り、通貨換算、Wikipedia本文抜粋、書籍検索、生命科学文献、USGSの重要地震、World Bankの首都・人口、Hacker Newsの技術記事、日本の祝日、計算、世界時計。続く質問に都市や日付、書籍・文献の検索条件を引き継ぎます。「できること」で用途を検索できます。端末内モデルを読み込むと、文章作成・翻訳・要約・コードの説明も試せます。

## 端末内LLM

アプリを開くと、全4モデルを順番に読み込んで準備します。初回はモデル合計約2.7GBに加え、実行ファイルを取得します。実行は1モデルずつ行い、初期設定では準備後に標準のQwen3-1.7Bを起動します。「端末内AI」で4モデルの準備状況を確認し、別モデルを選んで「選択したモデルを起動」で固定して使えます。固定したモデルは、端末が対応していれば次回の一括準備でも最後に起動します。ブラウザーが保持している取得済みファイルは再利用します。

初期設定の「用途に合わせてモデルを自動選択」では、その端末で準備に成功したモデルの中から、コード相談にQwen2.5-Coder-1.5B、文章・会話にQwen3-1.7Bを使います。`コード:`や先頭の言語名、コード相談に続く「もっと短く」「別の例」などを識別します。`文章作成:`・`翻訳:`・`要約:`は標準用途に戻します。未準備・準備失敗・GPU非対応の場合は現在のモデルを使い、自動選択のためだけに新しいモデルを取得しません。切替中も入力欄近くの「停止」で中断でき、失敗後に別モデルの取得や再試行を続けません。

モデルを手動で起動すると自動選択を解除します。チェックを入れ直すと自動選択へ戻せます。設定と固定モデルは同じブラウザー内に保存します。質問に対する正しいモデルの判定や生成内容の正しさを保証するものではなく、1モデルずつ実行するため切替の待ち時間があります。

一括準備中もAPI照会・計算を使えます。LLM生成は準備終了後に利用します。「一括準備を停止」または入力欄の「停止」で中断すると、停止設定を保存し、再読込時に勝手に再開しません。「全モデルをまとめて準備」で再開します。GPU非対応端末ではGPUモデルを未対応と表示し、CPU互換モデルを準備します。別の端末・ブラウザーではそれぞれ初回取得が必要です。

一般的な質問は従来のAPI・計算処理を優先し、`文章: お礼メールを作成`、`翻訳: ここに文章`、`要約: ここに文章`、`コード: JavaScriptの配列を説明`で生成を指定できます。モデルが利用可能なら、対応するAPI処理のない依頼にも生成で応答します。

| 選択肢 | 用途 | モデルの取得量の目安 | 実行方式 |
| --- | --- | --- | --- |
| Qwen3-1.7B | 会話・文章の標準候補 | 985 MB | WebGPU |
| Qwen3-0.6B | 軽量な短文。日本語の品質には限界あり | 352 MB | WebGPU |
| Qwen2.5-Coder-1.5B | コード相談 | 881 MB | WebGPU |
| Qwen2.5-0.5B | 互換モード。英語の短文向け。日本語・翻訳は不得手 | 約520 MB | CPU / WASM |

すべて元モデルはApache-2.0です。変換済みモデルを公開リポジトリの固定リビジョンから取得し、WebLLM 0.2.85 / Transformers.js 3.8.1を使用します。ライセンス本文・提供元は[MODEL_NOTICES.txt](MODEL_NOTICES.txt)を参照してください。1モデルずつ読み込み、停止・読み込み解除でWorkerを終了します。途中で停止・失敗した生成文は「未完」と明記して残し、次の生成用の会話条件には加えません。再開にはモデルを再読込します。コードを自動実行しません。

料金を請求する推論サービスへの接続はありません。通信量、電力、端末容量は利用します。WebGPUの対応、GPUメモリ、ブラウザのWASM制限などにより、すべての端末での動作は保証できません。CPUモードも遅い端末や容量不足では利用できません。GPUメモリ目安はダウンロード量や端末の総必要RAMとは別です。ブラウザのキャッシュは再利用される場合があり、解除してもファイルを削除しません。

生成中は入力を外部の推論サーバーへ送りません。ただしGAS接続時は、生成への質問・回答も通常の会話履歴として管理者のスプレッドシートに保存します。APIの本文や過去のAPI回答をモデルへ自動投入せず、LLMの短い会話履歴だけを引き継ぎます。特にopenBD等の原文表示が必要なデータを勝手に書き換えません。最新情報・計算はデータ照会で確認し、生成文には誤りがあり得ます。

1回の生成はGPUで最大384トークン、CPUで最大160トークンです。文字数とは異なります。上限到達・終了理由不明を画面で知らせ、未完の出力を次回の生成条件へ加えません。Qwen3では反復を抑えるサンプリング設定を使い、14〜120文字の同じ表現が末尾で4回連続した場合は停止して原文と理由を残します。明示的な反復依頼やコードブロックにはこの停止を適用しません。反復の完全な防止や、依頼の全条件を満たす文章品質を保証するものではありません。文章作成・翻訳・要約は用途別の指示を補い、翻訳本文の全角文字や記号は書き換えずに渡します。

## 端末内でできること

- 単位換算：`5kmは何マイル？`、`1ポンドをkgに換算`、`32°Fは何℃？`。長さ・常衡質量・面積・体積・温度に対応します。フィート・マイルは国際定義を用い、ガロンなど定義の紛らわしい単位は含めません。表示は最大13桁に丸めます。換算後の`cmなら？`は元の数量を引き継ぎます。
- 日付計算：`今日から100日後は何日？`、`2026/10/25の3日前`、`2026年10月25日は何曜日？`。
- 日数差：`2026-10-25から2027-01-01まで何日？`。開始日を0日として数えます。日付の「今日」は端末の時計による日本時間です。グレゴリオ暦の西暦1〜9999年を扱い、実在しない日付は自動補正しません。

## 営業日で計算する


`2026-10-30から3営業日後は何日？`、`今日から5営業日前は？`で、土日と日本の祝日を除いた前後の日付を計算します。開始日を0日として数え、0日後は休日でも開始日と同じ日付です。

`2026-10-01から2026-10-31までの営業日は何日？`は、両端の日付を含む期間内の営業日数を返します。同じ営業日だけなら1日、同じ休日だけなら0日です。日付を逆順で指定すると、同じ範囲の日数を負数で返します。通常の暦の日数差とは数え方が異なります。

祝日は[Holidays JP](https://holidays-jp.github.io/)の登録不要・MITの既存APIから取得し、取得済みデータを再利用します。提供元は前年・当年・翌年を収録します。年初の日付を含めてデータの形式を確認し、収録されていない年を平日として推測しません。会社独自の休業日や年末年始休業は加えません。例えば12月31日が平日で祝日でなければ営業日として数えます。除いた土日・平日の祝日の数と出典を表示します。

`土日のみ除く: 2026-10-30から3日後は何日？`なら、祝日を数え、土日のみを除外します。この指定は外部API・LLM不要です。前後の計算は1000日、期間の計算は3660日以内です。

単位換算と通常の暦の日付計算では外部APIを呼びません。GAS接続時の会話保存は通常どおり行います。換算係数の出典は[NIST Guide to the SI](https://www.nist.gov/pml/special-publication-811/nist-guide-si-appendix-b-conversion-factors)です。

## 条件を引き継ぐ通貨換算

`100万円は何ドル？`、`1.5億円をユーロに換算`、`USD 100をJPYに換算`のように、万・億の倍率とISO通貨コードの前置・後置を扱います。対応通貨はUSD/EUR/JPY/GBP/CNY/KRW/AUD/CAD/CHFです。金額は0〜1兆。万・億は数値に1つ付ける表記に対応し、`1億2000万円`のような複合表記は確認を促します。桁区切りの不正や負の金額を、別の数値へ読み替えません。

換算後の`200なら？`は通貨ペアを保って金額だけを変更し、`ユーロにすると？`は金額と換算元を保って換算先を変更します。`200ドルなら？`は金額と換算元を変更し、換算先を維持します。`逆にすると？`は同じ金額のまま通貨ペアを入れ替えます。`ユーロなら？`のように方向が曖昧な場合は確認を促します。まとめて質問した場合も、直前に成功した処理の条件を次の依頼に引き継ぎます。

レートには既存の[Frankfurterの無料公開API](https://frankfurter.dev/)を使用します。指定ペア・正の有限数・実在するレート日を検証し、最大12桁で概算を表示します。同じペアの取得済みレートを再利用し、同じ通貨の換算ではAPIを呼びません。両替・決済手数料は含まず、リアルタイム相場ではありません。

## 基準地点の周辺にある記事を探す

`周辺記事: 京都駅`、`京都駅の周辺の記事`で、日本語Wikipediaの主座標付き記事を距離順に探します。`周辺記事: 京都駅、半径3km`で範囲を指定できます。半径は100m〜10kmの整数メートルで、初回は1km。20件まで取得し、5件ずつ表示します。「他の記事」で続き、「半径3kmなら？」や「もっと広く」で先頭から範囲を変えます。「大阪なら？」は半径を保って基準地点を変えます。単一の都市を調べた後なら「その周辺の記事」も使えます。

登録済み都市名はアプリの代表座標を使い、「東京駅」を「東京」の代表座標へ置き換えません。その他の地点は既存のWikipedia座標検索で地球上の主座標を探し、選ばれた記事名・記事リンクと小数4桁の基準座標を表示します。同名・曖昧な地点は基準の記事を確認してください。緯度・経度、記事ID、距離を検証してから表示します。

[MediaWiki Geosearch](https://www.mediawiki.org/wiki/API:Geosearch)の公開APIを使用します。新たな登録・キー・有料接続は不要です。1ページずつ順に実行し、取得済みの応答を再利用します。GASは既存のWikipediaプロバイダー設定に従い、固定の検索件数・記事名前空間・主座標と小さい半径だけを許可します。ブラウザからのWikipedia取得には識別用Api-User-Agentを付けます。

記事の名称・座標を表示する検索で、図書館・博物館・観光施設を網羅する一覧ではありません。歴史的な場所や事件の記事を含むこともあります。実データで所在地説明と登録座標の不一致も確認したため、距離を「登録座標間」と表示し、各記事の登録座標も添えます。徒歩経路・営業状況・現在利用できることを表しません。空結果を「施設が存在しない」とは言い換えません。元記事の著者・ライセンスへのリンクを表示し、本文の取得やLLMによる施設情報の補完は行いません。

## 日本の祝日を会話で確認

`来年の日本の祝日`は日本時間の現在年から翌年を求めます。「11月だけ」で前の照会年を保って絞り込み、「来年は？」は月を保って現在年の翌年へ切り替えます。「年間一覧」で月の絞り込みを解除します。「次の祝日」は当日を含む先頭5件で、年末は翌年の登録も使います。

`2026-11-03は祝日？`、`11月3日は祝日？`で日付の登録を確認します。年を省略した月日は前の日本祝日の照会年、条件がなければ日本時間の現在年を使います。`2026-10-26から8日後は何日？。その日は祝日？`のように、直前の日付計算の結果を参照できます。「翌日は？」は前に確認した日の翌日、「明日は祝日？」は日本時間の今日の翌日です。参照日がないときは日付指定を促します。

祝日登録のない日を営業日とは断定しません。未収録年と不正日付は「祝日なし」にせず、条件を案内します。[既存のHolidays JP](https://holidays-jp.github.io/)のMIT公開データを使い、年初の元日を含めて形式と収録年を確認します。推測で祝日を補いません。新しい外部接続や権限は追加しません。

## 英国3地域の祝日

`2027年のイギリスの祝日`は、イングランド・ウェールズ／スコットランド／北アイルランドを分けて表示します。`スコットランドの次の祝日は？`は英国時間の当日を含む、今後の先頭3件です。「スコットランドなら？」は年・一覧／次の条件を維持し、「来年は？」は英国の現在年から翌年を求めて年別一覧に切り替えます。「日本の祝日」は既存の日本向けデータを使います。

[英国政府の公開API](https://www.api.gov.uk/gds/bank-holidays/)の固定JSONのみを取得します。登録・キー不要、© Crown copyright / [Open Government Licence v3.0](https://www.nationalarchives.gov.uk/doc/open-government-licence/version/3/)で商用・非商用に無償利用できます。提供元・ライセンスを表示し、名前と振替日の注記は原文のまま表示します。取得済みデータは最大1時間再利用します。

Bank holidayは銀行休業日の登録情報で、店舗・学校・勤務先すべての休業を表すものではありません。取得できた年だけ回答し、未収録年や範囲末尾から将来の日付を補いません。各年の一覧は地域ごと最大24件。月日指定・英国の営業日計算には未対応で、条件を黙って無視せず案内します。未対応国の祝日を日本の祝日に置き換えません。

## 分野をまたぐ学術検索

`学術検索: quantum computing`、`学術検索: education`で、Crossrefに登録された学術資料を検索します。1ページ3件、先頭から最大5ページです。「学術検索の続き」で同じ検索語の次ページへ進みます。既存の`論文: sleep`は引き続き生命科学中心のEurope PMCを使用します。

`DOI: 10.1038/nphys1170`または`https://doi.org/10.1038/nphys1170`で、Crossrefに登録された識別子の書誌を確認できます。他の登録機関のDOIや、一部の記号を含むDOIには未対応です。取得項目はDOI・タイトル・著者・刊行日・掲載媒体・資料種別の6項目に固定し、抄録・本文・引用文献は取得対象に含めません。

論文・会議論文・書籍章・投稿資料等を区別し、日付は提供元の精度のまま表示します。月しか登録されていない場合に1日を補いません。DOIは資料の識別子であり、査読済み・内容の正しさ・無料の本文へのアクセスを保証しません。

利用する[Crossrefの公開REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)は無料・登録不要です。GASでは全利用者を通じて同時照会1件、取得完了後1.1秒以上の間隔を設けます。別の照会中は案内して停止し、自動再試行しません。429/503では既存の待機・キャッシュの仕組みを使います。有料のMetadata Plusや推論APIには接続しません。

## 会話を参照リンク付きで書き出す

左側の「会話をテキスト保存」、またはヘッダーの設定から「会話をテキストで確認・保存」を開きます。スマートフォンでは設定から使えます。開いた時点の質問・回答・記録された参照リンクを確認し、「テキストを保存」でUTF-8 BOM付きのzero-conversation.txtを保存できます。保存が制限される環境では「テキストを選択」で本文だけを選び、通常のコピー操作で取り出せます。クリップボードへの自動書き込みや外部サービスへの送信は行いません。

回答ごとにHTTPSの参照URLを付け、同じ回答の重複URLは整理します。記事・著者履歴・ライセンス等のリンクを残し、生成文に記録がない出典やモデル表記を付け足しません。履歴の読み込みでも参照先を保持します。古い履歴で既に欠落したリンクは復元できません。本文はコードの空白や日本語を保ち、入力欄は1つのままです。処理中や会話が空の場合は保存・選択を無効にし、不完全な内容を書き出しません。

新しい保存では参照先を重複除去後に最大64件、JSON全体40000文字まで保持します。URLは1200文字までで、上限超過時にURLや後半の参照先を切り捨てず、保存できないことを案内します。画面内の書き出しは保存前の参照先も保持します。保存失敗時でも画面にある回答を確認・書き出せます。従来の先頭12件での切り捨ては廃止しました。

## 書名・著者名から本を探す

`本: space` はキーワード、`書名検索: Dune` は書名、`著者検索: Tolkien` は著者名でOpen Libraryを検索します。1回5候補、最大5ページ・25候補です。`本の続き`、`ほかには？` は検索語と検索方法を保って次ページへ進みます。`書名検索なら？`、`著者検索なら？`、`キーワード検索なら？` は同じ検索語で方法を変え、1ページ目へ戻ります。会話履歴からも同じ条件を引き継ぎます。

作品単位の書誌として、書名・著者（3名まで、残りの人数を併記）・提供元の初刊年・作品ページへのリンクを表示します。版・翻訳の一覧や無料で読める本文の一覧ではありません。書名・著者名の検索は完全一致を保証せず、提供元の関連度順です。正確と示された件数と参考件数を分け、参考件数だけで続きを打ち切りません。候補が尽きた場合や5ページの上限では照会前に案内し、6ページ目を5ページ目へ丸めて再表示しません。

取得項目は既存の4項目に固定します。応答のページ・件数・作品ID・書名・著者を検証し、不正な応答や取得失敗では前の検索条件を上書きしません。初刊年の欠落や形式を確認できない値を0年にしません。検索結果は更新で順序が変わる場合があります。24時間以内で応答を再利用し、GASの既存の1.1秒以上の取得間隔・共有待機に従います。登録フォームの送信や個人の連絡先の追加、書影・本文・貸出APIの取得は行っていません。

## 百科事典の候補から記事を選ぶ

`検索: ジャガー`、`オーロラとは？` はWikipediaの候補を最大3件、検索順位付きで表示します。候補のボタンか `2番を詳しく` で記事を選ぶと、その記事IDだけを取得します。選択前の `もっと詳しく` は、複数候補から自動で1件を決めず選択を案内します。選択後は同じ記事の冒頭を表示し、`候補に戻る` は保存された候補一覧を追加照会なしで表示します。会話履歴を開き直しても候補番号と選択を引き継ぎます。

検索時は冒頭550文字、選択した記事は仕様上限内の1200文字を要求します。提供元により多少長い場合や、冒頭が短いため増えない場合があります。全文やLLMによる統合要約ではありません。曖昧さ回避ページはその旨を明示し、特定の意味の説明として本文を出しません。各記事の原文・著者編集履歴・著作権へのリンクを添え、最大24時間再利用します。削除や異なる記事IDの応答を、別の記事で補いません。

ボタンは記事IDに結び付くため、別の検索をした後に古いボタンを押しても、そのボタンの記事を開きます。画面と会話履歴には記事名を表示します。候補に本文は保存せず、IDと名称だけを会話条件へ保持します。

## 風速・湿度も予報から確認

`東京の明日の風速は？`、`東京と大阪の2026-10-28の湿度` に対応します。既存のMET Locationforecast compactの同じ応答を使うので、別のAPI・キー・課金枠は追加しません。通常の天気にも風速・湿度を添え、単独で聞いた項目は大きく表示します。

風速は地上10mの10分平均風速について、取得した予報時点の最大値です。瞬間最大風速ではありません。湿度は地上2mの相対湿度の最小〜最大です。有効な値と対象日の時点数を表示し、日平均や中央値は算出しません。温度と風速・湿度は別に欠測を扱い、温度が未収録でも風速だけの予報を表示できます。風速のm/s、湿度の%を応答の単位情報で確認し、負値や範囲外の湿度、単位不一致を0に置き換えません。

風速を照会した後の `湿度は？` は同じ都市・日付を保ちます。`大阪なら？` や年月日の変更では項目を維持し、`明日は？` は現地の明日へ切り替えます。新しく `東京の天気` と聞くと通常表示へ戻ります。都市未指定なら項目と日付を保って都市名を尋ねます。突風・風向・室内湿度・警報・安全判断は対応項目と混同せず案内します。今日から9日後までの、取得した予報に値がある日だけを扱います。

## 技術ニュースを読み進める

`技術ニュース` はHacker Newsの注目順、`新着の技術ニュース` は新着順、`高評価の技術ニュース` は高評価順の一覧です。1回5候補、先頭25候補・5ページまで表示します。続けて `ニュースの続き`、`次のニュース`、`ほかには？` で次ページへ進み、`新着なら？`、`高評価なら？`、`注目順なら？` で一覧を切り替えます。改行した複数依頼でも順番に条件を引き継ぎます。

最初の一覧のIDと取得日時を会話に保持するため、続きを開く途中で順位が変わっても別の一覧へ入れ替えません。10分を過ぎた続きは、新しい一覧を開くよう案内します。会話履歴からも期限内なら続けられます。スコア・コメント数は取得時点の値で、投稿時刻は日本時間と明示します。削除・非表示・未収録は表示せず、別記事を追加取得して穴埋めしません。一部の取得失敗は一覧位置を示し、全件失敗では前の条件を維持します。

Hacker Newsの原文タイトル、記事・求人・投票の種類、議論へのリンクだけを使い、本文やコメント本文、投稿者の個人情報は取得しません。一般ニュースの網羅検索や、分野・地域・日付による絞り込みではありません。公式の固定3一覧と記事IDの経路だけを既存プロバイダーで取得し、有料サービスやアカウントは追加しません。

## 保存とアクセス

GAS接続時は質問・回答・会話条件を保存します。ブラウザ内で作った256ビットのランダムな識別情報をリクエストごとに送信し、サーバーではSHA-256ハッシュとして照合します。他の利用者の会話一覧・本文は返しません。同じブラウザ・プロファイルを共有する人は同じ履歴にアクセスできます。ブラウザデータを削除した場合や、ブラウザが埋め込み画面のストレージを制限した場合、過去の履歴に再接続できないことがあります。この識別方式はGoogleアカウント認証の代わりとなる機密データ保管の仕組みではありません。

スプレッドシートの管理者は保存された会話を閲覧できます。データベースの共有範囲は拡大しないでください。GASのWebアプリはデプロイしたユーザーとして実行します。公開URLには匿名アクセスを許可しますが、履歴の取得・保存は識別情報ごとに制限されます。

## 通信と表示

年ごとの推移は `日本の人口の推移`、`2020年から2025年の日本とアメリカのGDP推移` で質問できます。期間を省くと今年を含む10暦年、`過去5年なら？` なら今年を含む5暦年になります。1960年以降、今年までの連続した1〜20年を指定し、同じ指標で最大3か国・地域を比較します。`平均寿命は？`、`スイスなら？`、`平均寿命の推移`、`グラフにして`、`同じ期間でGDPは？` では指定済みの期間を維持し、`最新では？` で最新の単年値へ戻れます。

グラフは0から共通の上限までの目盛を使い、未収録年では線を切ります。年別の表にもすべての対象年を表示し、欠測を0や他年の値で補いません。現在年を含む指定でも、その年の統計がまだ公表されていないことがあります。表は会話の保存・テキスト書き出しにも含まれます。新しく照会した結果の「年別データをCSV保存」から、取得成功した国・地域の全対象年を1ファイルに保存できます。数値には画面用の丸めを加えず、未収録は空欄と状態列で区別します。単位・指標コード・出典URL・CC BY 4.0・取得日時を含み、追加照会はしません。UTF-8 BOM付き・CRLF区切りです。保存済み会話はテキスト表示のためCSVボタンは復元されません。同じ質問で再照会すると保存できます。GDPは名目米ドルの系列であり、物価や為替の影響を除いた実質成長率としては扱いません。

日の出・日の入りは `東京の2027-01-01の日の出` のように年月日で指定できます。このアプリでは2000〜2099年に対応します。`翌日なら？`、`前日なら？`、`大阪なら？` で確定した日付から続けられ、`今日は？` で現地の今日へ戻れます。地点が未指定なら日付を保って地点名を尋ねます。

提供元の太陽周期の基準日と、日の出・日の入りの実際の年月日を分けて表示します。高緯度などではイベントが前日・翌日になることがあります。nullは「時刻なし」、項目の欠落は「未収録」と表示し、白夜・極夜や天気を推測しません。未知の地点で時間帯を特定できない場合はUTCと明示します。天文学的な時刻で、地形や実際の見え方とは異なります。

国の統計は `日本とアメリカのGDP`、`2020年のスイスとノルウェーの1人当たりGDP`、`南アフリカの平均寿命` で照会できます。人口も同じ仕組みで公表年を表示します。既知の国に加え、World Bankの国・地域一覧から日本語名、提供元の英語名、2・3文字の国コード（例：CH・CHE）を照合します。同じ指標で3か国まで比較できます。最新は数値が収録された最新年を国ごとに取得するため、比較する年が異なる場合があります。

国一覧は必要な場合だけ取得し、地域集計を除いて照合します。2026-10-26の取得時点では217の国・地域が対象でした。すべてが独立国という意味ではなく、4指標の収録も国・地域と年によって異なります。日本語名は端末の地域名データを使うため、端末によって表記が異なる場合があります。見つからない場合は英語の正式名か国コードを指定してください。部分一致で別の国へ置き換えません。カンマやandを含む名称は `「Congo, Dem. Rep.」の人口` のように引用します。

続けて `2020年なら？`、`平均寿命は？`、`フランスなら？` と指定すると国・年・指標の条件を引き継ぎます。`最新では？` で最新へ戻ります。新たに国と指標を両方明示した質問も最新を使います。年は1960年以降、今年までの1年を指定でき、未収録を0や別の年の値で埋めません。GDPは当年価格・名目米ドル、1人当たりGDPは所得・給与とは異なり、平均寿命は出生時の平均余命で個人の寿命予測ではありません。実質GDP、購買力平価、成長率、期間集計は別指標のため代用しません。

天気は `東京の2026-10-28の天気` のように西暦を含む年月日で指定できます。`大阪なら？` で同じ日付を維持し、`2026-10-29なら？` で日付を変更、`今日は？` や `明日は？` で相対日の指定へ戻れます。都市が未指定なら日付を保ったまま都市名を尋ねます。今日から9日後までを受け付けますが、実際に取得した予報に含まれる日の値だけを表示します。日付は都市の現地時間、時間帯が未特定の地点はUTCで区切ります。

過去の実測天気には対応していません。不正日、過去日、遠い将来、期間・曜日・時刻の指定や欠測を今日の予報に置き換えません。取得した時間別予報からの集計で、1日全体を含まない場合や将来の予報間隔が広がる場合があります。降水量は対象日に収まる区間だけを合計し、日付をまたぐ区間を推計で分割しません。日本の1都市の日付が確定した後は「その日は祝日？」にも引き継げます。

過去の為替換算は `2025-01-15の100ドルは何円？` と指定できます。`200なら？` や `ユーロにすると？` では日付を維持し、`2025-01-18なら？` で日付を変更、`最新のレートで` で日付指定を解除します。年月日を1日ずつ指定し、1948-01-01以降、今日（日本時間）までを受け付けます。実際の収録期間は通貨ペアによって異なり、取得できなかった場合に最新レートで代用しません。

指定日とAPI返却日を表示します。返却日が指定日より前ならその相違を案内し、後なら換算を停止します。提供元の日次集計であり、API返却日を個々の市場・銀行の公表日や実際の決済日とみなしません。期間集計や日中の売買レート、手数料の計算には対応していません。

日時の時差変換は `時刻変換: 東京 2026-11-01 10:00 → ニューヨーク`、`東京の午後3時はロンドンで何時？` のように聞けます。日付を省くと変換元の都市の今日を使い、解決した日付を表示します。登録済み都市・UTC・有効なIANA時間帯名を受け付け、曖昧な略称から地域を推測しません。`14:30なら？`、`ロンドンなら？`、`逆にすると？` にも対応します。逆方向は同じ瞬間を保って変換します。

夏時間終了などで現地時刻が複数回ある場合は「早い方」「遅い方」を選びます。夏時間開始などで存在しない時刻は、自動補正せず案内します。外部APIやLLMは使わず、ブラウザーのIntlと端末のタイムゾーンデータで計算します。将来の制度変更の反映はブラウザー・端末の更新に依存し、最新の規則が常に反映される保証はありません。

複数の依頼は「それと」「そして」、改行、句点、セミコロンで区切って送れます。例：`5kmは何m？それとcmなら？そして今日から100日後は何日？`。前の処理の結果で会話条件を更新してから、次の依頼を解釈します。本の題名などに区切りの語を含む場合は`本:「昨日。そして明日」`のように引用してください。引用・括弧内は分割しません。1回の実行は4件までで、残りや未対応の依頼は案内します。

提供元がHTTP 429または503を返した場合は、接続先ごとに新しい照会を停止します。`Retry-After`の秒数・日時指定を優先し、指定がなければ通常60秒、辞書の429では次のUTC正時まで待機します。GAS側は利用者間で待機期限を共有します。期限内でも有効なキャッシュや端末内処理は利用できます。自動再試行や別の接続先への切り替えは行いません。

現地の時間帯を未登録の都市は、天気・天文の日付と時刻をUTC基準と明示します。世界時計は登録済みの時間帯だけで回答します。回答完了後は会話欄を結果の末尾までスクロールします。

## 速度・時間・データ量の換算と会話の続き

`60mphは何km/h？`、`90分は何時間？`、`1GiBは何MB？`を外部通信なしで計算します。速度はm/s・km/h・mph・kn、時間の長さはms・s・min・h・dです。日は24時間固定で、月・年の日数や夏時間を含む暦の期間には換算しません。データ量はB・kB（KBも可）・MB・GB・TB、KiB・MiB・GiB・TiB、bit・kbit・Mbit・Gbit・Tbitです。Bはバイト、bはビットとして区別します。データ量の英字記号は大文字・小文字を厳密に扱い、mbなどは意味を推測せず案内します。

換算後の`MiBなら？`、`それをMiBにして`は元の数量と元単位を保ちます。`2なら？`は元単位での数量だけを変更し、`逆にすると？`は同じ数量のまま元単位と変換先を入れ替えます（直前の計算結果を入力に戻す操作ではありません）。`1GiBは何MB？。2なら？。逆にすると？`のような複数依頼や保存済み会話の復元後にも条件を引き継ぎます。失敗した換算では条件を更新しません。時間の長さとデータ量は0以上、数量の絶対値は10の15乗まで、異なる種類間の換算は停止します。表示は最大13桁で、内部計算はJavaScriptの浮動小数点数です。通信速度やファイル転送時間は扱いません。

定義の確認先：[NIST換算係数](https://www.nist.gov/pml/special-publication-811/nist-guide-si-appendix-b-conversion-factors)、[NISTの時間単位](https://www.nist.gov/pml/special-publication-811/nist-guide-si-chapter-5-units-outside-si)、[NISTの2進接頭語](https://physics.nist.gov/cuu/Units/binary.html)。

## 地震の公開記録を条件付きで調べる

`最近の地震`はUSGSの重要地震の過去7日です。`過去1時間の重要地震`、`過去24時間の重要地震`、`過去30日の重要地震`も指定できます。`日本周辺の過去24時間のM4.5以上の地震`は別のM4.5以上の公式フィードを使い、`M5以上`など4.5〜10の下限で絞れます。M4.5以上フィードは24時間だけを許可し、長い期間を重要地震へ黙って置き換えません。

1ページ5グループ、最大5ページ・25グループを時刻の新しい順で表示します。「地震の続き」「世界なら？」「日本周辺なら？」「重要地震なら？」「過去30日なら？」で条件を継続・変更します。「条件をリセット」で世界の重要地震7日に戻ります。会話履歴からも条件を復元します。取得済みフィードは最大5分使い、更新によってページの件数・順序が変わる場合があります。フィード作成時刻と照会時刻を別々に示します。

日本周辺は北緯20〜48度・東経122〜155度の固定範囲です。市町村・他国ごとの検索、指定した暦日、予測・震度・警報・津波の照会は対応範囲を案内し、世界の記録などへ読み替えません。記録の欠測を0にせず、発生時刻・規模・座標の完全一致だけをまとめ、元記録を残します。対象はearthquakeの記録で、重要地震はUSGSの分類です。全世界のすべての地震を網羅せず、緊急地震速報でもありません。未掲載は地震が発生していないことを意味しません。

[USGS公式GeoJSON仕様と固定フィード](https://earthquake.usgs.gov/earthquakes/feed/v1.0/geojson.php)、[USGSの著作権・クレジット方針](https://www.usgs.gov/information-policies-and-instructions/copyrights-and-credits)を確認。USGSの出典とイベントへのリンクを表示し、日本の防災情報は気象庁へのリンクで案内します。

## 出版年とOAで生命科学の文献を絞る

`論文: sleep | 年:2024 | OAのみ`、`論文: memory | 年:2020-2024`でEurope PMCの書誌を検索します。`2024年の睡眠の論文`も使えます。検索語80文字まで、出版年は西暦1000年から日本時間の現在年までです。範囲は開始年から終了年の順とし、条件の重複や未知の指定を黙って捨てません。「睡眠・栄養・運動・記憶・学習・免疫」の完全一致は登録済み英単語へ置き換え、実際の検索語を表示します。その他はそのまま送信します。

`文献の続き`で同じ語・年・OA条件の次の5件へ進みます。`2023年なら？`、`OAのみなら？`、`OA条件を解除`、`年の条件を解除`は他の条件を保ち、先頭から検索します。新しい明示的な検索は条件をリセットします。最大5ページ・25候補です。次の位置が欠ける・繰り返される場合は停止し、最初のページに読み替えません。履歴復元後も条件とカーソルを引き継ぎます。取得済み検索結果は最大24時間再利用するため、提供元の更新で一致件数や順序が変わる場合があります。

年はAPIのPUB_YEAR（出版年）で、FIRST_PDATE（初回公開日）とは異なる場合があります。OAはAPIのisOpenAccessフラグで、再利用ライセンス・査読済み・研究の品質の判定ではありません。元記事の条件を確認してください。返された年・OAが指定条件と異なる場合、識別子・件数・検索語やカーソルの応答が要求と異なる場合は表示を停止します。掲載媒体や著者等の未収録を補いません。抄録・本文・診療上の結論は取得・生成しません。長い書誌文字列は省略記号を付け、元記事にリンクします。

[Europe PMC公式API仕様](https://dev.europepmc.org/RestfulWebService)、[公開検索項目の公式リファレンス](https://dev.europepmc.org/docs/EBI_Europe_PMC_Web_Service_Reference.pdf)、[EMBL-EBI利用条件](https://www.ebi.ac.uk/about/terms-of-use/)を確認しています。
